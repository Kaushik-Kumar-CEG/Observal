# Local follow-sync QA only

This disposable fixture **does not enable production follow-sync**. `app.py` explicitly registers the 17 otherwise-unregistered endpoints alongside the normal accepted-v1.2 mobile activity/evidence, auth/device/config routes, for two independent loopback API processes, separate privacy and projection queue pollers, and real authenticated session ingest and layer-snapshot routes behind one local HTTPS nginx issuer. PostgreSQL 18, Redis and ClickHouse 26.6 run in newly named disposable containers on random loopback ports, with no shared volumes or production/Flare access. ClickHouse migrations and `services.clickhouse.schema.init_clickhouse` apply and read back both source TTLs before the synthetic follow fixture opens its read barrier; startup fails closed if verification fails. Before exposing the public CA, `up.sh` runs the installed Pi SDK with a deterministic no-model transcript and the real Pi extension against same-issuer authenticated ingest, waits for the real projection worker to derive MCP/skill/hook facts from retained ClickHouse source, validates final receipts/source TTL and both disposable mobile viewers' positive three-kind v1.2 capabilities. This proves source mapping and transport, **not a real model, launched MCP tool, protected Flare trace or production capability**; no typed fact or capability flag is manually forged. Do not run on a shared or remotely reachable host. The synthetic read barrier opens **only in the disposable database** for 60 minutes on scratch, or up to 120 minutes for a separately named 18446 Android session; it never opens protected stores. Expiry closes access but does not authorize teardown. No protected accounts or fixtures are read.

Prerequisites: Docker daemon, OpenSSL, curl, Python 3, Node 22+ and local Pi SDK at `~/.local/npm/lib/node_modules/@earendil-works/pi-coding-agent/dist/core/session-manager.js`, `observal-server/.venv` installed from the server lockfile (`cd observal-server && uv sync`), and a web build from this checkout. While ANY other QA issuer is open, build only into an isolated public-asset directory (e.g. `cd web && pnpm typecheck && pnpm exec vite build --outDir /tmp/observal-follow-qa-assets.<unique> --emptyOutDir` then `chmod 755` that public directory). Never replace another issuer's mounted `web/dist`. Docker images `postgres:18`, `redis:7-alpine`, `clickhouse/clickhouse-server:26.6`, `nginx:alpine` must be available; install/pull in advance if offline. The script refuses `observal-server/.env` and scrubs inherited environment for all server commands (including any production URLs/tokens); use a clean checkout. Never run the script with sudo. Check `git status` before and after; no Android repository is touched.

The old 18443 session is **unknown-owned**. Never run `up.sh` or `down.sh` with the default `.runtime` marker while it remains. For a disposable scratch on separate port 18444, from repo root:

```bash
export MOBILE_FOLLOW_QA_STATE_NAME=.runtime-scratch-a1b2c3 MOBILE_FOLLOW_QA_PORT=18444
export MOBILE_FOLLOW_QA_WEB_DIST=/tmp/observal-follow-qa-assets.<unique> # existing, public assets only, directory mode 0755
qa=tests/integration_mobile/local_follow_qa
"$qa/up.sh" # automatic Pi source + positive both-role capability check + per-IP auth cooldown
id=$(<"$qa/$MOBILE_FOLLOW_QA_STATE_NAME/id")
observal-server/.venv/bin/python "$qa/verify.py" # DESTRUCTIVE scratch only; API POST /consent is fixture setup, NOT a browser consent pass
MOBILE_FOLLOW_QA_EXPECT_ID="$id" "$qa/down.sh" # only after proving this scratch is yours
```

The `18443` marker, listener, process identities, stores and CA are never affected by an `18444`/`18446` cleanup. Do not distribute the CA key or runtime directory. Use the CA file only for the current session; it expires in two days and changes at every start.
