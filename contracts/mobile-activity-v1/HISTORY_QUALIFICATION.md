# Historical local-source qualification — **no central-ping person traces**

The Company pulse screenshot shows separate aggregate events, prompts, tool calls and active users. The central usage-ping payload is deployment-wide and has **no named uploader, registered component/version, event-time original author or verified run/root lineage**. Never point a phone at that collector or relabel those totals as Author/User. This server's **local** `session_stats_agg` can inform a separately permissioned general/platform metric only; it is not a source of typed person-component traces or supported zeroes.

The new bounded **read-only** `scripts/audit_mobile_history.py` checks only local, retained `session_events FINAL` source, in memory. To run on an **owner-authorized, disposable loopback-only** database, set `MOBILE_LOCAL_HISTORY_AUDIT=1`, `DATABASE_URL` and `CLICKHOUSE_URL` to literal `127.0.0.1` origins, preferably with read-only database credentials. The script refuses DNS aliases (including `localhost`) and non-loopback DSNs, disables inherited HTTP proxies, and exits before making a database connection otherwise. Never use an SSH tunnel or forwarded protected instance. Its output is grouped by `1w`/`1m`, Pi/unsupported harness and MCP/skill/hook kind plus separately suppressed `legacy_pi` User/Author MCP previews, with only five-or-more candidate-root cells visible; small cells, unknown, missing or expired source are `not_recorded_or_suppressed`, **not zero**. The CLI caps a scan at **10 source sessions and 30 seconds** (the internal function enforces an absolute 50-session maximum) and reports `incomplete` on overflow, never a partial-page cohort total; a timeout exits without any aggregate. A previous private observation of 39 sessions therefore **cannot** be described as a complete output from this default 10-session CLI scan. A separately scoped larger scan needs owner approval and its own bounds. It does not print user/session IDs, code, raw transcript, pin contents or small-cell counts, mutate databases, enqueue jobs or create phone grants.

A **v2/v3** Pi candidate needs all of: server-stored uploader UUID resolving to an active local user; offset-zero, contiguous, nontruncated retained source with conservative all-row TTL floor; a source-hash-matching Pi session header and server-witnessed parent-free root; all layer hashes registered for exactly that actor/harness with complete pin cardinalities; result-linked MCP calls (not alias-only tool arguments), exact installed skill-content read-result pins, or hook command-binding receipts; explicit event time; a live original-author provenance row and **recorded approved publication** for the pinned version at that time; current public visibility. Children, missing authors/old pre-045 approvals, unverified parents, ambiguous aliases, changed skill reads and invented hook receipts remain unqualified. Client-reported skill/hook facts are still partial evidence, not independent execution attestation. An eligible audit candidate is **not** an already-published positive and never automatically opens a read cohort.

**Pre-v2/v3 Pi source is not silently upgraded.** The new `services/mobile_legacy_attribution.py` is a read-only conditional preview for old 16-hex layer hashes: source must be retained and complete with its original ingest-time SHA-256 on **every** raw line, wholly legacy, parent-free, uploader-bound, and absent from the modern run table; its one exact uploader/project/hash snapshot must have been uploaded before the event, carry a self-consistent Pi manifest with an MCP config and a unique explicit Pi MCP alias/component/version pin, and its adapter-linked tool call/result must match that alias at an explicit time. A current public, already-released registry version **and** a separately server-verified, complete alias/component/version pin predating the call are required even for a prospective **User** typed partial candidate; captured original author and recorded event-time approval are additionally required for a prospective **Author** candidate. A fabricated old client pin pointing at an approved public listing cannot ascribe typed activity to **either** person. Standard old pre-v2 snapshots have no independently verified pin and therefore yield **no named typed candidates**. Their separate User `general_sessions` observation can still be useful without inventing component identity. The LOCAL audit shows these in **separate five-or-more suppressed** `legacy_pi.user`/`legacy_pi.author` candidate buckets only. Old hashes without trustworthy pins, pre-045 author/publication provenance, or ambiguous snapshots yield no named typed reading, **not zero**. The on-device User `general_sessions` metric can separately observe a complete, retained, prompted old Pi root under the User-specific read barrier; it remains Partial, never a typed call or Author fact, and refuses mixed old/new or previously registered roots. Neither preview writes facts to the database or responds on typed phone routes. Admission of any old typed candidate to a phone would require a separately authorized, deletion-safe backfill design and target qualification; do not claim it is shipped.

**Backfill already exists for verified v2/v3:** `scan_retained_mobile_sources` keyset-scans retained Pi v2/v3 source in bounded passes, requires a user and verified layer, and idempotently upserts only the existing `mobile_projection_queue`; `project_pi_session` serializes each scope, checks full source revision/retention and exact root/pin/typed event evidence, rechecks source before commit, and publishes through the normal epoch/retention/erasure barrier. The v2/v3 audit is stricter for a preview root and **does not bypass** that projector or its deletion-safe replay. Old source has no server-witnessed nonce and is intentionally never passed to that projector. The worker's scanner may find a qualified local subset; it cannot reconstruct evidence deleted by TTL, pre-045 original authors/publication transitions, or automatically upgrade preexisting Pi clients. Missing historic coverage stays Partial or Not recorded while new verified usage works.

**Protected internal/dev:** code review is **not** permission to inspect them. An operator must first identify the actual server ID, endpoint, source retention and running revisions out of band, obtain target-owner data-access approval and minimum-cell agreement, run a separately reviewed aggregate-safe read-only plan there, then decide whether any existing source qualifies. Do not run this loopback-only script against a tunnel, central usage-ping service or unapproved cohort. Do not enable named reads to conduct the audit. A release merge or old dashboard metric never creates past component provenance.
