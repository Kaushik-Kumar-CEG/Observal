# Historical local-source qualification — **no central-ping person traces**

The Company pulse screenshot shows separate aggregate events, prompts, tool calls and active users. The central usage-ping payload is deployment-wide and has **no named uploader, registered component/version, event-time original author or verified run/root lineage**. Never point a phone at that collector or relabel those totals as Author/User. This server's **local** `session_stats_agg` can inform a separately permissioned general/platform metric only; it is not a source of typed person-component traces or supported zeroes.

The new bounded **read-only** `scripts/audit_mobile_history.py` checks only local, retained `session_events FINAL` source, in memory. To run on an **owner-authorized, disposable loopback-only** database, set `MOBILE_LOCAL_HISTORY_AUDIT=1`, `DATABASE_URL` and `CLICKHOUSE_URL` to literal `127.0.0.1` origins, preferably with read-only database credentials. The script refuses DNS aliases (including `localhost`) and non-loopback DSNs, disables inherited HTTP proxies, and exits before making a database connection otherwise. Never use an SSH tunnel or forwarded protected instance. Its output is grouped by `1w`/`1m`, Pi/unsupported harness and MCP/skill/hook kind, with only five-or-more candidate-root cells visible; small cells, unknown, missing or expired source are `not_recorded_or_suppressed`, **not zero**. The CLI caps a scan at **10 source sessions and 30 seconds** (the internal function enforces an absolute 50-session maximum) and reports `incomplete` on overflow, never a partial-page cohort total; a timeout exits without any aggregate. It does not print user/session IDs, code, raw transcript, pin contents or small-cell counts, mutate databases, enqueue jobs or create phone grants.

A Pi candidate needs all of: server-stored uploader UUID resolving to an active local user; offset-zero, contiguous, nontruncated retained source with conservative all-row TTL floor; a source-hash-matching Pi session header and server-witnessed parent-free root; all layer hashes registered for exactly that actor/harness with complete pin cardinalities; result-linked MCP calls (not alias-only tool arguments), exact installed skill-content read-result pins, or hook command-binding receipts; explicit event time; a live original-author provenance row and **recorded approved publication** for the pinned version at that time; current public visibility. Children, missing authors/old pre-045 approvals, unverified parents, ambiguous aliases, changed skill reads and invented hook receipts remain unqualified. Client-reported skill/hook facts are still partial evidence, not independent execution attestation. An eligible audit candidate is **not** an already-published positive and never automatically opens a read cohort.

**Backfill already exists:** `scan_retained_mobile_sources` keyset-scans retained Pi v2/v3 source in bounded passes, requires a user and verified layer, and idempotently upserts only the existing `mobile_projection_queue`; `project_pi_session` serializes each scope, checks full source revision/retention and exact root/pin/typed event evidence, rechecks source before commit, and publishes through the normal epoch/retention/erasure barrier. The audit is stricter for a preview root and **does not bypass** that projector or its deletion-safe replay. The worker's scanner may find a qualified local subset; it cannot reconstruct evidence deleted by TTL, pre-045 original authors/publication transitions, or automatically upgrade preexisting Pi clients. Missing historic coverage stays Partial or Not recorded while new verified usage works.

**Protected internal/dev:** code review is **not** permission to inspect them. An operator must first identify the actual server ID, endpoint, source retention and running revisions out of band, obtain target-owner data-access approval and minimum-cell agreement, run a separately reviewed aggregate-safe read-only plan there, then decide whether any existing source qualifies. Do not run this loopback-only script against a tunnel, central usage-ping service or unapproved cohort. Do not enable named reads to conduct the audit. A release merge or old dashboard metric never creates past component provenance.
