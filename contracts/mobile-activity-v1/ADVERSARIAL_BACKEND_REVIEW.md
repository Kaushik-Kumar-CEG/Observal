## 2026-10-17 independently prompted AI review — four reproduced source defects, **not human signoff**

The dedicated `reviewer` subagent remained unavailable because `claude-sonnet-4-5` is ambiguous and its providers unauthenticated. Instead an isolated text-only Pi reviewer, explicitly pinned to the authenticated `azure-openai-responses/gpt-6-sol`, read only branch/source docs and reported **four concrete issues**. The backend author inspected the exact referenced code and added focused regressions; this is **AI-assisted author remediation, not independent human security/privacy approval**.

16. **P1: queue held selected child locks while projecting a selected parent in another transaction.** The parent re-enqueues its qualified child and could wait on the outer queue worker's child row lock, making the parent projection stall/time out repeatedly. Changed the queue to one atomic `FOR UPDATE SKIP LOCKED` 50-row **three-minute committed lease** before any nested projection, with `attempts` incremented at claim. Each projection result commits separately, and exact `requested_at=:claimed` compare-and-swap deletes/reschedules preserve a concurrent parent re-enqueue. A killed worker eventually retries instead of abandoning work. A two-row parent/child mock regression asserts the claim transaction commits before replay, and poison-queue retry tests assert the CAS and bounded claim. The **exact new claim SQL** was accepted by a bounded, read-only `EXPLAIN` on the fresh live 061 PostgreSQL without updating any row; the claim-and-project worker itself has **not** run in a final-image Android fixture. Validate actual parent/child concurrency on a new consented disposable target before rollout.
17. **P2: self-User tool-free Partial 0 omitted publication's source retention floor.** Despite a complete ClickHouse check, a publication could describe a supported zero in the 29–30-day raw-line margin after its conservative `source_retained_until`. The self-zero candidate query now requires `pub.source_retained_until>now()` just like the typed positive path; a targeted test guards the exact SQL and missing/expired source stays **Not recorded**. The revised zero query passed bounded read-only `EXPLAIN` on the actual fresh 061 PostgreSQL (no person rows fetched); a full retained-history/expiry PostgreSQL acceptance on a revised image remains to do.
18. **P2: malformed duplicate Pi read result was ignored when counting linked results.** One valid byte-for-byte read plus a second same-ID result missing boolean `isError` could qualify a skill load. Every same-ID result, even malformed, now counts for uniqueness; only **one explicitly `isError=false`** result can qualify. Focused missing/string/null duplicate regressions pass; neither a skill CLI hint nor changed/truncated content is upgraded to an execution claim.
19. **P2: a PostToolUse hook receipt could appear after its supposed linked result.** The installed sender emits call→receipt→result. The parser now requires its same-generation unique well-formed result's offset strictly after the receipt and counts malformed same-ID duplicates. Focused valid order, late result, absent `isError` and duplicate tests pass. Hook outcomes remain uploader-bound reports, never launcher/model-choice attestation.

## Boundaries rechecked

- **Arithmetic and provenance:** The common typed SQL uses `COUNT(DISTINCT (actor, root_run_incarnation))` for a person's union, separate filtered MCP/skill/hook measures, same-uploader layer/component pin, retained publication status, prospective original author, event-time approval and current public listing/version visibility. The 10K fixture asserts 40 calls on one root = one root; the Pi SDK uploader→running worker→HTTPS fixture asserts MCP+skill+hook = three overlapping rows but one person root for each permitted scope. Hash/string/binary count-key experiments were reverted: no weaker key was shipped.
- **Root/child and v3 sender:** `mobile_run_identity.py` rejects new identity on legacy source, header mismatch, same session ID/new incarnation, ambiguous parent cycles, time-inconsistent hops and unresolved same-actor roots. Pi lifecycle origin and hook receipts remain uploader-bound client reports, **not independent attestation**. Skill load requires contemporaneous Pi advertisement, exact installed path/content pin and linked nonerror result; hooks require event/command digest pin, call and generation, with strict PostToolUse result now added. The sender's hook receipt contains only digest, event, call, outcome and exit code; command stdout/stderr are ignored. Raw Pi transcript upload still contains user/tool content as an existing observability source: privacy/retention review is mandatory and no claim of transcript-wide pre-send secrecy is made.
- **Auth and alternate routes:** ES256 mobile audience and scope reject browser/CLI use, while legacy `require_role`, snapshots and subscriptions reject phone JWTs. Public GraphQL `{health}` intentionally returns the same value anonymously and to a phone bearer; private GraphQL subscriptions call legacy JWT auth on subscription and each event. Admin/log/snapshot paths do not accept mobile audience. Fresh real HTTPS tests cover credential proof, legacy whoami/snapshot denial, GraphQL public equivalence, same-role unlisted cohort denial and refresh/logout replay.
- **Deletion/replay/privacy:** The project advisory shared read lock and exclusive retention barrier serialize source-derived reads against asynchronous ClickHouse deletion. A late uploader/source revision cannot silently re-admit old facts; scope, listing and source epochs reject stale anchors and keyset cursors. Fresh HTTPS tests mutate hook visibility and require 409 old revision and Not recorded rather than a false hook zero. Synthetic routine-test teardown reblocks, disables auth and clears settings, waits for source deletion before deleting users. The separate held Android fixture was destroyed on explicit owner acknowledgment **before** expiry: an independent supervisor blocked reads, disabled flags, stopped TLS/API, removed joint and upgraded PostgreSQL/ClickHouse/Redis volumes (including source/facts/users/signing keys) and deleted protected credentials/TLS material.
