# Backend adversarial review — author-performed, **not independent human review**

Reviewed the whole `origin/main...feat/mobile-trace-headlines` scope (92 files at initial review, plus final guard changes) by tracing the public sender→ingest→worker→typed SQL→phone route boundaries, migrations, retention, and relevant negative tests. Reviewer-agent invocation failed because its selected provider was unauthenticated. This report records *author* review and running-stack evidence; the user must independently inspect the entire final diff before even a draft PR.

## Concrete findings addressed

1. **Android rejected valid mixed-kind coverage.** The isolated capabilities endpoint advertised only MCP despite source-backed MCP+skill+hook Partial readings. `src/live/traceClient.ts` requires every reading coverage kind to appear in capabilities, so a v3 app would fail as incompatible. Fixed `api/routes/mobile_activity.py` to advertise only observed positive types to the exact synthetic viewer (including skill-only) and to remain false without the exact server, viewer, ack, barrier and source. Regression: `tests/test_mobile_activity_api.py` and actual two-viewer scoped HTTPS proof on the held Pi SDK source.
2. **A valid phone JWT could bypass the app's UI capability gate.** Previously `get_mobile_user` allowed direct named mobile API calls whenever phone auth was on, even if neither an owner-qualified production cohort nor the synthetic viewer allowlist matched. Fixed `services/mobile_read_control.py` and `api/deps.py`: all named phone data paths require a barrier-bound exact cohort; discovery/credential proof and revocation remain accessible independently. `app_factory.py` emits a **bodyless 403** for unlisted same-role viewers. The official fresh API/worker test obtains an actual device grant for an unrelated demo admin, proves its capability is false and its named Author detail is bodyless 403, then logs out; the two allowed synthetic principals retain their data.
3. **No operator could enable the accepted live capability without another code change.** The response hard-coded `trace_headlines=false`. It is now default-off but explicitly enableable only with `mobile.auth_enabled`, unblocked project control row, exact target `server_id`, the literal all-three-kind owner qualification ack and the `trace_headlines` switch. A stale synthetic allowlist cannot take over on missing production approval or during rollback. In-process tests cover wrong identity, missing approval, switch-off, barrier and audience separation. `REAL_INSTANCE_QUALIFICATION.md` gives owner-approved enable/reblock order; these code paths have **not been exercised against a protected target**, nor has the owner approved a real cohort.
4. **A post-tool hook receipt could claim a run with no tool result.** The prior matcher checked a preceding assistant tool call but did not require a same-generation result for `tool_result` receipts. Fixed `services/mobile_pi_hook_receipts.py` to require exactly one linked subsequent-to-call result; added forged missing/duplicate result and legitimate positive tests. This does not turn client-report receipts into independent launcher attestation.
5. **Installed Android exposed a cross-stack ClickHouse password collision missed by mocked/direct HTTPS tests.** An ordinary actor had a valid scoped 1W User card, but own `/summary` fetched general prompted roots from ClickHouse and received HTTP 401 (Code 194), surfacing as API 500 and an Android “Reading unavailable” page. `docker/docker-compose.yml` mounted all of `docker/clickhouse/users.d` writable: the image entrypoint wrote ignored `default-user.xml` into the Git worktree and other isolated stacks overwrote that password. Changed the bind to **only** the tracked `memory.xml` read-only, leaving each container's `users.d` writable inside the container for its own env-bound credential. Removed the ignored password file without printing its contents; reblocked the joint read barrier before repair, verified retained Pi source and three facts, then reopened only the original two viewers. Final official fresh/upgraded images both used the repaired configuration; the fresh real HTTPS regression now requests the actor's **own** User `/summary`, not just their page and another viewer's summary. Scoped HTTPS retest on the held Android fixture: actor and rotated author each got 200 cards, summary, three-row page and all three details. The owner independently confirmed in the installed no-Metro QA APK: ordinary actor own User union=1, MCP/skill/hook row=1 each and all details, count-free other-person Author; rotated author own Author union=1 and all three details.

## Boundaries rechecked

- **Arithmetic and provenance:** The common typed SQL uses `COUNT(DISTINCT (actor, root_run_incarnation))` for a person's union, separate filtered MCP/skill/hook measures, same-uploader layer/component pin, retained publication status, prospective original author, event-time approval and current public listing/version visibility. The 10K fixture asserts 40 calls on one root = one root; the Pi SDK uploader→running worker→HTTPS fixture asserts MCP+skill+hook = three overlapping rows but one person root for each permitted scope. Hash/string/binary count-key experiments were reverted: no weaker key was shipped.
- **Root/child and v3 sender:** `mobile_run_identity.py` rejects new identity on legacy source, header mismatch, same session ID/new incarnation, ambiguous parent cycles, time-inconsistent hops and unresolved same-actor roots. Pi lifecycle origin and hook receipts remain uploader-bound client reports, **not independent attestation**. Skill load requires contemporaneous Pi advertisement, exact installed path/content pin and linked nonerror result; hooks require event/command digest pin, call and generation, with strict PostToolUse result now added. The sender's hook receipt contains only digest, event, call, outcome and exit code; command stdout/stderr are ignored. Raw Pi transcript upload still contains user/tool content as an existing observability source: privacy/retention review is mandatory and no claim of transcript-wide pre-send secrecy is made.
- **Auth and alternate routes:** ES256 mobile audience and scope reject browser/CLI use, while legacy `require_role`, snapshots and subscriptions reject phone JWTs. Public GraphQL `{health}` intentionally returns the same value anonymously and to a phone bearer; private GraphQL subscriptions call legacy JWT auth on subscription and each event. Admin/log/snapshot paths do not accept mobile audience. Fresh real HTTPS tests cover credential proof, legacy whoami/snapshot denial, GraphQL public equivalence, same-role unlisted cohort denial and refresh/logout replay.
- **Deletion/replay/privacy:** The project advisory shared read lock and exclusive retention barrier serialize source-derived reads against asynchronous ClickHouse deletion. A late uploader/source revision cannot silently re-admit old facts; scope, listing and source epochs reject stale anchors and keyset cursors. Fresh HTTPS tests mutate hook visibility and require 409 old revision and Not recorded rather than a false hook zero. Synthetic test teardown reblocks, disables auth and clears all synthetic settings, waits for source deletion before deleting synthetic users; the independent expiry watchdog also closes and clears flags before stopping API/TLS. No already-sent response bytes can be recalled.
