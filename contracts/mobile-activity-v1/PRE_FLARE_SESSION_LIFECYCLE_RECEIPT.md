## Backend behavior and bounded evidence

- Reproduced 068 failure **red**: disabled mobile issuance returned 503 **after** `GETDEL` consumed the saved grant. Now PostgreSQL's shared issuance transaction lock and active-account check precede Redis mutation. Mobile-only refresh atomically swaps predecessor and successor JTIs in **one real Redis Lua execution** while checking account/device revocation, and never caches raw tokens or an idempotent reply. Duplicate and revoked predecessors cannot mint another successor. The successor and its access JWT retain the original family deadline; initial families are capped at 30 days even if browser/CLI refresh settings are longer. Legacy longer mobile grants require fresh approval. Browser/CLI paths retain their own settings and existing success wire.
- A concurrent terminal SCIM deactivation or reactivation takes the operator issuance lock and permanently raises the Redis account marker **before** committing the status change. Redis failure aborts the status transaction. A reactivated account cannot reuse a previously authorized phone family; only a newly approved grant minted after the marker qualifies. Reversible operator pause is not equivalent to SCIM account revocation. Mobile logout's device marker covers the signed family and access deadlines even if dynamic settings shorten later. Credential proof and protected reads still reject revoked/deactivated users and Redis outages before JWT expiry.
