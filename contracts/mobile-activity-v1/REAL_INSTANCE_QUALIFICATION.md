# Real-instance trace qualification (operator gate, not a deployment authorization)

Run this only with the **instance owner's explicit written permission** for the named server, viewer role, candidate period and aggregate inspection. Do not query private sessions, names, bearer tokens, raw prompts, arguments, transcripts, CA keys or individual source paths for an unapproved cohort. Do not use a synthetic fixture, installation ping, generic session total or a PR test as evidence of live coverage. Record only counts after an approved minimum-cell policy; if a count is below the privacy threshold, record `suppressed`, not its exact value. No step here flips `mobile.auth_enabled`, `trace_headlines`, the read barrier or test-mode allowlists.

## Deployment and isolation gate

1. Owner identifies the exact HTTPS origin, API/worker image revisions, PostgreSQL Alembic head, ClickHouse migration head and signing-key/JWKS rotation state. Verify both API and worker use the **same reviewed commit**, the current linear schema and the accepted v1.2 four-file SHA-256 manifest. Do not infer an active worker from API `/readyz` alone. Compare deploy configuration against reviewed Docker Compose, including read-only API root and telemetry delivery. Missing/mismatched state: **stop**.
2. Owner verifies dedicated `observal-mobile-activity-v1` bearer audience, `mobile:read`, device family binding, exact verification origin on server-issued device challenge, TLS trust without a fallback to forwarded Host, authenticated `/auth/mobile/credential` proof before persistence, single-use refresh and logout/revocation under Redis fail-closed. Desktop bearer must not reach phone-only routes; phone bearer must not reach legacy/session/GraphQL/snapshot feeds. Check GraphQL authorization and subscriptions, snapshot/Insights paths and logs for alternate named-person or secret-bearing payloads. Missing guard or exposed old image: **stop**.
3. Keep scoped `trace_headlines=false` and phone issuance default off during qualification. Only an owner-approved rollout plan may change those switches, after security/privacy review of entire diff and recipient roles. The ephemeral `synthetic_test_cohort` flag and its old server/viewer IDs **must be absent** on the target.

## Provenance, coverage and retention gate

4. Determine the **first** deployment time at which Pi sender (CLI and extension), authenticated uploader, worker, parser, source retention and mapping version all produced corroborated records. Only event windows **after** this boundary can be considered. Pi root/parent/incarnation witnesses are client-reported and same-uploader source-checked, not independent launcher attestation. Exercise child-before-parent reprojection, nonce/header/uploader mismatches, source repair, repeated delivery, unknown/missing layer mapping and replay before admitting any root. No retrofit of past usage pings.
5. Inspect source and projection health for the requested period through **aggregate-safe** counters only: upgraded sender versions, accepted/rejected source sessions, bounded/truncated records, retained ClickHouse revisions, queued/pending/partial projector status, disqualified roots, mapping ambiguity, event-time publication/version approval, prospective original-author coverage and erasure/TTL progress. Compare accepted source revisions to published PostgreSQL generations and identify gaps; a missing source, unbounded lag, stale deletion barrier or no reproducible retention check means **Not recorded or Partial**, never supported zero.
6. Qualify each *kind and harness separately*. At this fork's MCP-only state, Pi result-linked verified-layer `mcp_calls` permits **positive Partial** original-author or self-User distinct-root lower bounds, plus a very narrow source-checked **self-User tool-free Pi MCP Partial zero**. It does not certify Author zero, all-kind zero, complete period coverage, skill load, hook run, Claude Code, other harnesses or real-origin attestation. Skill advertisement is not load; plain user text or the `/skill` expansion is not invocation. A Pi read must be advertised-at-that-offset, result-linked and matched to the same verified install fingerprint before considering a skill **load**. A Pi hook custom receipt is at most client-reported extension evidence; require verified event/command binding, a preceding real tool call, result consistency, same uploader/generation and a currently visible reviewed hook. No unverified kind may join a person union or `supported_kinds`.
7. Prove PostgreSQL authorization/privacy and mutation invalidation on the **actual deployed versions**: distinct `(actor, root incarnation)` unions with overlapping component rows, event-time approval plus current public visibility, original author surviving transfer, named-person roles independent of Follow, no private self-use except the subject's own User scope, and count-free mixed Restricted/bodyless denied endpoints. Rotate a source/approval/privacy epoch and require old scoped cursors to return 409, not stale named data. Run deletion and ClickHouse retention under the read lock; until the purge finishes and source revalidation succeeds, leave the barrier closed. A mocked unit test alone is not sufficient.
8. Record representative *aggregate-only* latency from an authorized instance of the expected size (100 follows/10K roots is a synthetic stress fixture, **not a target count**). Capture bounded p50/p95 of a twelve-subject batch and 21-row keyset page with actual indexes and query plans, without logging IDs or SQL bind values. Check response sizes and mobile pagination termination; do not extrapolate a disposable database's p95 to production.

## Permissioned UI gate

9. Only after the owner signs off cohorts, visibility and roles may a test maintainer receive a scoped real-instance credential. Use the **existing** server-issued verification origin on HTTPS, not a local rewrite of the Host header. Compare each permitted, named person at 1W and 1M from retained qualified source → projection → authenticated API → Android card/page/detail under the same window/revision. Confirm distinct-root arithmetic (forty calls on one root remains **one**) without publishing raw identities. Have a second non-admin account attempt the same Following/private/detail route; it must see Restricted or bodyless denial, never inherited access. Test logout, account switch, stale page, refresh replay and one deletion during a pending read. Stop and reblock if any named-person leakage or unsupported-zero claim appears.

The separate synthetic Android UI journey is recorded in the shared mobile `BACKEND_ANDROID_ACCEPTANCE.md`; it does **not** meet steps 4–9 for a real cohort. An instance owner must supply the authorization and aggregate-safe operational facts. This runbook grants no access to `internal.observal.io`, `dev.observal.io`, or any other deployment and requires no private-data inspection to conclude **not yet qualified**.
